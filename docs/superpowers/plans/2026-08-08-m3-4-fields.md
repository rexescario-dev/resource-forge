**Package:** `@resource-forge/core`  
**Slice:** M3.4 only — Field / `FieldName` + ordered `fields` sequence + Resource validation; projection non-participation

**Goal:** Widen `ResourceSchema.fields` from the empty-only placeholder to an immutable ordered sequence of closed name-only Fields with unique `FieldName`s, validate that sequence as part of `validateResource`, and keep `projectResourceMetadata` free of any field→metadata contribution.

**Architecture:**

```text
candidate fields sequence
          │
          ▼
 validate candidate member shape   ← closed `{ name }` only; extra props → failure (no stripping)
          │
          ▼
 validate names + uniqueness       ← FieldName grammar + duplicates → failure
          │
          ▼
 snapshot exact valid Fields       ← freeze ordered `{ readonly name }` only; never lossy-normalize candidates
          │
          ▼
       Resource.schema
          │
          ▼
    validateResource               ← authoritative Resource gate; still-empty relations/operations; no silent normalize
          │
          ▼
 projectResourceMetadata           ← revalidate Resource; annotation-derived metadata only (RFC-006); fields contribute nothing
```

**Invariant:** No implementation step may transform an invalid candidate into a valid Field by discarding information before validation.

`FieldName` is a dedicated Resource-local identity domain (not `MetadataKey`). `Field` is closed: `{ name: FieldName }` only. Declaration order is semantically meaningful. Equality of sequences is order-sensitive (test/internal helper only; public Resource equality remains deferred).

**Tech Stack:** TypeScript strict, Vitest (existing `packages/core` scripts)

Where this plan and an Accepted specification disagree, the specification wins and this plan must be revised.

## Locked decisions (export / shape review — planning aids)

These freeze the M3.4 implementation surface. They MUST NOT invent product semantics beyond RFC-007.

| Decision | Lock |
| --- | --- |
| `FieldName` | Validated string matching `/^[a-z][a-zA-Z0-9]*$/` exactly. The label “camelCase” is descriptive only — not an extra constraint. Exact string equality; no normalization. |
| `Field` | `{ readonly name: FieldName }` only. Extra properties → `invalid_field_member`. |
| `fields` representation | **Implementation-level:** `ReadonlyArray<Field>`. Array index **is** semantic order (unlike annotations). |
| Empty `fields` | Zero-length array; still produced by `createEmptyResourceSchema` / `createResource`. |
| `relations` / `operations` | Remain `EmptySchemaCollection` (`readonly []`); non-empty → `invalid_schema` (no field cause). |
| `EmptySchemaCollection` | Keep for relations/operations; **do not** type `fields` as always-empty. |
| Snapshot construction vs validation | **Separated, non-lossy.** Raw candidate validation (closed shape, names, uniqueness) happens **before** any snapshot that materializes `{ name }` only. `snapshotFields` accepts only already-validated `Field` members and freezes an ordered sequence; it MUST NOT discard, strip, or normalize unknown properties. `validateResource` is the final Resource validity gate; it MUST NOT silently rebuild or reorder caller-owned sequences as its primary job. |
| Non-empty Resource construction | **No public builder.** Public `createResource(identity)` remains empty schema collections + empty annotations. Tests needing non-empty `fields` use an **internal** fixture seam (not barrel-exported) that validates candidates before snapshotting. |
| Internal helpers | `validateFieldName` / `checkFields` (or equivalent candidate validators) / `snapshotFields` / `fieldsEqual` are **internal or test-only**, not public product APIs. Public validation remains `validateResource`. |
| Validation ownership | Part of `validateResource` via schema. No public `validateFields` / `validateResourceSchema`. |
| Schema error taxonomy | Field failures: `invalid_schema` **with** `cause: FieldValidationError` using only `invalid_field_name` / `duplicate_field_name` / `invalid_field_member`. Non-field schema failures (missing collections, non-empty relations/operations, non-object schema): `invalid_schema` **without** field cause (same top-level code as M3.1). |
| Projection | After revalidation, still `createResourceMetadata(identity, [...annotations])` only. Fields MUST NOT contribute entries. |
| Reserved names | None. |
| Types / constraints / defaults | Out of scope. |
| Equality helper | **Test/internal only** `fieldsEqual` (order-sensitive). MUST NOT be a public product API. |
| Compose / registry | SHALL NOT require `composeResourceMetadata`; SHALL NOT register. |

### Field validation error shape (planning aid)

```ts
type FieldValidationError =
  | {
      readonly code: 'invalid_field_name';
      readonly index: number;
      readonly name: string;
    }
  | {
      readonly code: 'duplicate_field_name';
      readonly index: number;
      readonly name: string;
    }
  | {
      readonly code: 'invalid_field_member';
      readonly index: number;
    };

type ResourceValidationError =
  | {
      readonly code: 'invalid_identity';
      readonly cause: IdentityValidationError;
    }
  | {
      readonly code: 'invalid_schema';
      readonly cause?: FieldValidationError;
    }
  | {
      readonly code: 'invalid_annotations';
      readonly cause: AnnotationValidationError;
    };
```

M3.1 used `{ code: 'invalid_schema' }` with no cause. M3.4 **adds** optional `cause` for field failures only. Do not invent additional field cause codes for test convenience. Do not put relation/operation emptiness failures under the three field causes.

### Construction vs validation (normative for this plan)

| Concern | Owner |
| --- | --- |
| Validate raw candidates (shape / names / uniqueness) | Internal fixture / construction seam — **before** snapshot |
| Establish snapshotted ordered `fields` from **already-valid** Fields | Resource construction seams (`createEmptyResourceSchema` / `createResource` for empty; **internal** fixture for non-empty tests) |
| Decide validity of a Resource’s fields | `validateResource` (final gate on the constructed Resource) |
| Project metadata | `projectResourceMetadata` after revalidation — annotations only |

**Internal non-empty fields fixture seam:**

```ts
// internal / test-only — NOT exported from packages/core public API
// Candidates are opaque objects so extra properties remain observable at runtime.
function createResourceWithFieldsForTests(
  identity: ResourceIdentity,
  candidateFields: readonly object[],
  annotations?: Annotations,
): Result<Resource, ResourceValidationError>
```

`createResourceWithFieldsForTests` validates candidate member shape, names, and uniqueness **before** constructing the snapshot; successful construction freezes the ordered `{ readonly name }` members and then passes the resulting Resource through `validateResource`. Default annotations: `emptyAnnotations`.

Failure mapping for the fixture MUST use the same `invalid_schema` + `FieldValidationError` causes as `validateResource` (no silent success after stripping).

### Projection behavior (RFC-007 non-participation)

```text
projectResourceMetadata(resource)
  1. validateResource(resource)     // includes field validity rules
  2. on failure → invalid_resource
  3. createResourceMetadata(identity, [...resource.annotations])  // fields ignored
  4. on metadata failure → invalid_metadata (defensive)
  5. success → ResourceMetadata with identity + annotation-derived entries only
```

MUST NOT mutate Resource. MUST NOT invent field-derived metadata keys/envelopes.

## Constraints (from Accepted RFC-007)

### SHALL

- represent `fields` as an immutable ordered sequence of name-only Fields
- enforce `FieldName` grammar `/^[a-z][a-zA-Z0-9]*$/` as the sole name constraint
- enforce unique `FieldName`s within the sequence
- treat empty `fields` as valid
- validate `fields` as part of Resource validity via schema
- keep field errors distinct from metadata and annotation validation
- preserve declaration order in snapshots
- validate candidate closed shape / names / uniqueness before any lossy materialization of `{ name }`
- keep relations/operations empty-only in this slice
- leave projection free of field contributions

### SHALL NOT

- invent field types, nullability, constraints, defaults, or descriptions
- reuse `MetadataKey` for field identity
- reserve any `FieldName`s
- contribute fields to `projectResourceMetadata`
- silently drop, normalize, coerce, or reorder for semantic equality
- transform an invalid candidate into a valid Field by discarding unknown properties before validation
- introduce public `validateFields` / `validateResourceSchema`
- widen relations/operations beyond empty
- invent annotation vocabulary or cross-source merge
- export a new public Resource builder solely to support field tests
- export `fieldsEqual` / `validateFieldName` as public product APIs in this slice

## TDD / verification strategy

For each task: write failing tests → implement → green → commit.

**Must cover:**

1. Empty `fields` valid (M3.1 regression)
2. Valid ordered non-empty `fields` accepted via internal fixture; order preserved on Resource
3. Invalid `FieldName` (e.g. `Id`, `user-id`, ``) → `invalid_schema` / `invalid_field_name`
4. Grammar-valid but “odd camelCase” names (e.g. `userID`) **accepted** — regex is sole constraint
5. Duplicate `FieldName` → `invalid_schema` / `duplicate_field_name`
6. Extra property on member (e.g. `{ name: 'id', type: 'string' }`) → `invalid_schema` / `invalid_field_member` via fixture **and** via `validateResource` on a Resource that somehow carries a non-closed member — never accepted as `{ name: 'id' }` after silent strip
7. Snapshot-by-value / freeze: mutating caller-owned candidate array or member objects MUST NOT change `resource.schema.fields` (only after a **successful** validate-then-snapshot construction)
8. Order-sensitive equality (internal/test): `[id, email] ≠ [email, id]`
9. Non-empty `relations` or `operations` still → `invalid_schema` (no field cause required)
10. Projection: Resource with non-empty `fields` + empty annotations → identity + **no** metadata entries from fields
11. Projection: non-empty `fields` + non-empty annotations → annotation entries only (RFC-006 regression)
12. Projection: invalid fields → `invalid_resource`
13. Purity: projection does not mutate Resource / fields order
14. Public surface: `Field` / `FieldName` exported as planned; `validateFields` not exported
15. No field-type / constraint / reserved-name assertions

**Do not:** invent field→metadata keys; test field failures via `validateResource` / `invalid_resource` only.
